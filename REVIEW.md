# REVIEW.md

| # | Where (function / area) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---:|---|---|---|---|
| 1 | `compute_late_minutes` | The integer-minute threshold misses the strict boundary case: a punch at 09:40:01 for a 09:30 shift is late by 10 minutes, but truncating first produces 10 and the starter returns 0. It also has no attendance-day context for overnight shifts. | Test 09:40:00, 09:40:01, and 10:15:59 against a 09:30 shift; test an overnight employee. | Truncate timestamps to seconds, compare elapsed seconds strictly to 600, floor the full elapsed minutes, and calculate against the attendance day's shift start. |
| 2 | `compute_work_hours` | Python `round` uses ties-to-even, not the required half-up rounding. | Test a duration whose hours equal an exact half-cent boundary, such as 4.005 hours. | Use `Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | It always places shift end on the attendance date and counts every positive minute, even though overnight shifts end the next day and overtime is only counted from 30 minutes. | Test a 22:00–06:00 shift with a 06:20 and a 06:40 punch-out. | Build the correct shift-end instant for overnight shifts and apply the 30-minute threshold before flooring elapsed minutes. |
| 4 | `create_employee` and startup | Duplicate detection is check-then-insert and has no unique database index, so simultaneous creates can both pass the check. | Send parallel POST requests with the same `emp_code`. | Create a unique `emp_code` index at startup and translate `DuplicateKeyError` to 409. |
| 5 | `create_employee` | `datetime.now()` uses a naive local server timestamp and `created_at` is returned as a datetime rather than epoch milliseconds. | Run on a non-UTC host and inspect the response type/value. | Store a truncated UTC instant and serialize all API instants as integer epoch milliseconds. |
| 6 | `list_employees` | `skip = page * page_size` skips the first page, and `total` ignores the department filter. Results are not sorted and pagination is not bounded. | With page size 2, check pages 1 and 2; filter by a department with fewer employees than the whole collection. | Use `(page - 1) * page_size`, count the filtered query, sort by `emp_code`, and validate page/page size. |
| 7 | `punch_in` | An unknown employee causes a 500 when `emp` is dereferenced; timestamp conversion depends on the server timezone; the overnight attendance date is wrong; status/timestamp validation is missing. | Punch in for an unknown code, submit a seconds-looking timestamp, or use a 05:30 IST punch for a 22:00–06:00 shift. | Return 404 for an unknown employee, validate strict epoch milliseconds and status, normalize to UTC/IST, and calculate the attendance date using the shift. |
| 8 | `punch_in` | A read-before-insert duplicate check is race-prone, and the response exposes an `id` derived from MongoDB's internal `_id`. | Send simultaneous same-day punch-ins and inspect the response keys. | Enforce unique `(emp_code, date)` in MongoDB; return 409 for duplicate-key errors and never expose `_id` or an `id` alias. |
| 9 | `list_attendance` | It loads every matching document into Python and sorts/slices in memory, which will not scale to 100,000 records. Tie ordering is unspecified. | Seed a large collection and inspect memory/time; create same-date records for multiple employees. | Apply filtering, sorting, pagination, and total counting in a MongoDB aggregation, backed by indexes. |
| 10 | `list_attendance` | It returns MongoDB-derived IDs and raw BSON datetime values, and it does not validate date ranges/status/pagination. | Inspect a response or request `date_from` after `date_to`. | Serialize the public schema explicitly, exclude internal IDs, validate parameters, and return 422 for invalid ranges. |
| 11 | `health` | It always returns 200 without checking whether MongoDB is available. | Stop MongoDB and call `/health`. | Ping MongoDB and return 503 if it cannot be reached. |
| 12 | `app` startup / data access | No indexes are created, despite unique-key concurrency requirements and list/analytics performance requirements. | Inspect `getIndexes()` on a clean database and call explain on list/analytics queries. | Create idempotent unique and query-supporting indexes at startup. |
| 13 | Request models and routes | Starter models do not enforce the documented input constraints, and punch-out, regularization, analytics, and explain routes are missing. | Submit malformed timestamps/statuses or call each endpoint marked “You” in `openapi.yaml`. | Add validated request models and implement all required routes against the OpenAPI contract. |

## Reviewed and considered acceptable

- `emp_code` is the public employee identity; MongoDB `_id` must remain internal.
- `attendance_logs` should be addressed by the natural key `(emp_code, date)`, not by an API record ID.
- Calendar dates and shift times are strings, while instants are BSON UTC datetimes internally and epoch milliseconds at the API boundary.
- Loading `.env` for local development is acceptable because `python-dotenv` does not override real environment variables by default.
- The collections and status vocabulary in the starter match the supplied data model; the defects are in validation, calculations, concurrency, serialization, query strategy, and missing functionality.
